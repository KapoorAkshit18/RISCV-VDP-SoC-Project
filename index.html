RISC-V SoC with a Lightweight TPU Accelerator

A synthesizable RISC-V based System-on-Chip integrating a lightweight neural-network accelerator, memory-mapped peripherals, UVM-based verification, and formal protocol verification.

Overview

This project explores the integration of a lightweight neural processing accelerator into a RISC-V based SoC. The system combines processor-based execution with hardware acceleration while focusing on processor–accelerator communication, fixed-point computation, verification, and FPGA implementation.

RISC-V SoC

PicoRV32 based single-master SoC with memory-mapped RAM and peripheral interfaces.

TPU Accelerator

Lightweight neural-network accelerator using a 4×4 systolic processing-element array and fixed-point arithmetic.

Verification

SystemVerilog/UVM verification combined with reference modeling, functional coverage, assertions, and formal verification.

System Architecture

The SoC uses a single-master memory-mapped architecture. The PicoRV32 processor communicates with RAM and peripherals through a deterministic native interconnect.

TPU Accelerator

The neural accelerator implements a compact fixed-point datapath using a 4×4 systolic processing-element structure. Activations propagate horizontally while partial sums propagate vertically.

Accelerator datapath: MMIO configuration → AXI4-Stream payload generation → 4×4 systolic computation → sigmoid lookup → output

Processing Element

Each processing element performs the following fixed-point multiply-accumulate operation: 

y_out = y_in + ((a_in × b) >> 10)
  • Signed 16-bit operands
  • 32-bit multiplication
  • Arithmetic shift by 10 bits
  • 16-bit wrap-around arithmetic
  • No rounding
  • No saturation

Data Movement

The TPU receives neural-network payload data through an AXI4-Stream interface. The memory-mapped wrapper provides the processor-visible control and payload registers, while the streaming master transfers the configured data toward the neural accelerator.

Sigmoid Lookup Table

The accelerator uses a 256-entry sigmoid lookup table with Q6.10 output representation. The RTL lookup table is treated as the authoritative source for the software reference model, ensuring that simulation comparisons reproduce the implemented hardware behavior.

Processor–Accelerator Communication

Processor-to-accelerator communication was evaluated separately from the neural computation to quantify the overhead introduced by data movement and interface handshaking.

MMIO Control

Software configures the accelerator through registers exposed in the SoC memory map.

AXI4-Stream

Payload transfer uses VALID, READY and TLAST handshake semantics.

Control Status

Accelerator control includes START, BUSY and DONE behavior.

UVM Verification

The SoC was verified using a SystemVerilog/UVM environment with transaction-level stimulus, monitoring, scoreboarding, reference modeling, and functional coverage.

Figure 2 — UVM verification architecture

Reference Model

A cycle-independent C reference model was developed to reproduce the TPU's fixed-point computation, data mapping, systolic accumulation, and RTL sigmoid lookup behavior.

Reference model validation: 15 tests passed, 0 failed.

Scoreboard

The scoreboard compares DUT transactions against expected results generated by the reference model. Debugging included resolving mismatches involving payload mapping, timing assumptions, and reference-model behavior.

Formal Verification

Formal verification was used to check accelerator streaming protocol and control behavior independently from large neural datapath state spaces.

Figure 3 — Formal verification architecture and property boundaries

Verified Properties

Property Behavior
TPU_P01 VALID stability
TPU_P02 Payload stability
TPU_P03 Transfer qualification
TPU_P04 TLAST behavior
TPU_P05 START control behavior
TPU_P06 BUSY / DONE behavior

Formal Boundary Decomposition

Large datapath multiplexers created a significant SMT state-space bottleneck during full-design formal analysis. The verification boundary was therefore decomposed so that protocol and control properties could be analyzed independently from the large neural datapath.

The TPU streaming protocol was isolated using dedicated formal checkers, while START-control verification was moved to a smaller control boundary.
